## 致命的問題（WCAG AA違反 / 業務不可レベル）

### 1. すべてのフォームで `<label>` と `<input>` が紐付いていない（WCAG 1.3.1, 3.3.2, 4.1.2 違反）

`app/companies/new/page.tsx:96-99` を典型例として挙げる:

```tsx
<label className={labelCls}>企業名</label>
<input className={inputCls} placeholder="株式会社サンプル" />
```

`<label>` に `htmlFor` 無し、`<input>` に `id` も `aria-labelledby` も `aria-label` も無し。スクリーンリーダーでは「編集 空欄」としか読み上げられない。**91入力すべて**この状態。同パターンは下記でも確認:

- `app/companies/new/page.tsx` 全フィールド（企業名/カナ/業種/従業員規模/所在地/URL/設立年/CS担当/営業担当/契約金額/主担当/役職/メール/電話/Slack/メモ）
- `app/settings/products/new/page.tsx:107-` 全フォーム
- `app/settings/products/[code]/page.tsx:171-` 全フォーム
- `app/companies/[id]/CompanyDetail.tsx` ChurnModal フォーム全項目（`1019-1038`）
- `app/attendance/AttendanceClient.tsx:417-421` のチェックボックス
- `app/weekly/CompanyWeeklyEditor.tsx`、`app/weekly/WeeklyTable.tsx` の編集セル

**修正の方向性**: `id` を発行し `<label htmlFor={id}>` で結ぶ、もしくは `<input>` を `<label>` の中に内包する形に統一。`labelCls` ヘルパで統制が利いているので、修正コストは比較的低い。

### 2. モーダルが ARIA Dialog として実装されていない（WCAG 4.1.2, 2.4.3, 2.1.2 違反）

該当: `app/attendance/AttendanceClient.tsx:380-` (`ExpectedEditModal`), `app/companies/[id]/CompanyDetail.tsx:1008-` (`ChurnModal`), `app/settings/products/[code]/page.tsx:943-` (`ScheduleEditModal`)。

問題点（共通）:
- ルート `<div>` に `role="dialog"` も `aria-modal="true"` も無い
- `aria-labelledby` でタイトル要素 (`text-base font-semibold` の `<div>` や `<h3>`) と結びつけていない
- フォーカストラップが**完全に未実装**。Tab キーで背後ページにフォーカスが抜ける
- 開いた瞬間にフォーカスがモーダル内に移動しない（初期フォーカス未制御）
- 閉じた後、トリガーボタンへフォーカスが戻らない
- Escapeキーでの閉じる処理は `TopNav` の dropdown では対応しているが、上記モーダルでは未実装
- バックドロップ `onClick={onClose}` は問題ないが、その内側 `onClick={(e) => e.stopPropagation()}` のせいでクリックターゲットが意図せず広がる
- `ChurnModal` のクローズボタン `app/companies/[id]/CompanyDetail.tsx:1058-1065` の文字 `×` は U+00D7（乗算記号）。`aria-label="閉じる"` があるのは救い。`AttendanceClient.tsx:407` の `✕` には `aria-label` 無し。

**改善**: `radix-ui/react-dialog` 等の準拠ライブラリを採用して全モーダルを置き換えるのが最も低コストで確実。

### 3. ドロップダウンメニュー（通知・ユーザー）が WAI-ARIA Menu パターン非準拠

`components/TopNav.tsx:175-263` 通知パネル、`265-372` ユーザーメニュー:

- フォーカストラップ無し（Tab で背後ナビへ抜ける）
- Escapeで閉じるのは実装済み（`129-140`）— 評価点

### 4. 色のみによる情報伝達（WCAG 1.4.1 違反）

### 5. フォーカスインジケータの全面除去（WCAG 2.4.7 違反）

## 重要な懸念

### 7. 見出し階層の乱れ（WCAG 1.3.1, 2.4.6）

- `app/page.tsx:47` で `<h2>` を `text-sm font-semibold` で表示。視覚的サイズと意味的レベルの乖離が大きく、SR利用者の見出しジャンプ機能の有用性を損なう。
- `app/inbox/InboxView.tsx:263` の `<h2>` がリストアイテム内に出現。文書構造として不適切。
- `app/companies/[id]/CompanyDetail.tsx` のタブパネル内（数千行）に `<h3>` 以下が散在し、階層が一貫していない可能性が高い（要全件確認）。

### 8. クリックターゲットサイズ不足（WCAG 2.5.8 — AAA だが推奨）

- `components/TopNav.tsx:269` ユーザーアバター `w-8 h-8`（32px×32px）。AAA最小24px は満たすがAA推奨に届かない。
- `TopNav.tsx:163` ナビリンク `py-1.5`（高さ約26px）。モバイルで誤タップしやすい。
- `app/companies/new/page.tsx:186-200` のチェックボックス偽装トグルは `<input type="checkbox" className="hidden" />` で**完全に非表示**。フォーカスが当たらないため、キーボードで切り替え不可能（致命的に近い）。

### 9. レスポンシブ / モバイル対応の欠落

- `components/TopNav.tsx:155` の `<nav>` にハンバーガーメニュー無し、`md:hidden` 等の切替無し。10項目のナビ＋ロゴ＋通知＋アバターが幅 `max-w-[1400px]` 前提で並ぶ。タブレット縦持ちで完全にはみ出す。
- `app/page.tsx:154` 要対応企業テーブルが `min-w-` 指定無しで横スクロールも未制御。スマホでは崩壊。
- `app/weekly/WeeklyTable.tsx`, `app/onboarding/MatrixView.tsx` の sticky テーブルは横スクロール時のキーボード操作が困難。
- 全体的に `min-w-[1400px]` 前提のレイアウト設計で、200% ズーム（WCAG 1.4.10 リフロー）に未対応。

### 10. 極小文字の濫用（WCAG 1.4.4）

`text-[10px]` / `text-[11px]` が **373箇所**。例: `TopNav.tsx:152,194,236,194,...`、`HealthSection.tsx:119,121,...`、KPIカードのサブテキスト等。

10pxは `1.4.4` の200%拡大では20pxとなり仕様上はクリアできるが、デフォルト16px前提で設計されているUIにおいて10px起点で重要情報（金額、未読数、通知時刻、Health分類ラベル）を表示するのはロービジョン者・老眼ユーザーへの配慮不足。

### 11. アニメーション / モーション制御無し（WCAG 2.3.3）

## 改善提案（優先度順）

### P0（リリース前必須・1〜2週間）

1. **フォームの `htmlFor` 一括対応**: `useId()` で id 発行、`labelCls` ヘルパを `<label htmlFor>` 強制型に変更。91箇所の機械的修正。
2. **モーダルを Radix UI Dialog に置き換え**: 3モーダル（Expected/Churn/Schedule）。フォーカストラップ・初期フォーカス・Esc 閉じ・aria-modal を一括解決。
3. **`focus:outline-none` を全削除し `focus-visible:ring-2 ring-offset-2 ring-brand-blue` を Tailwind プラグイン or グローバル CSS で全フォーカス可能要素に標準適用**。
4. **スキップリンク追加**: `app/layout.tsx` 冒頭に `<a href="#main" className="sr-only focus:not-sr-only ...">メインコンテンツへスキップ</a>`、各 `<main>` に `id="main"`。
5. **色のみ情報の補完**: 行頭 Health ドットに `aria-label="健全度: 要対応"` 等を付与、`<title>` 追加。

### P1（1ヶ月）

6. **`hidden` チェックボックスの修正** (`companies/new/page.tsx:194`): `sr-only` + `peer` パターンに置換し、フォーカス可能・トラップ可能にする。
7. **ナビゲーションのレスポンシブ化**: `TopNav` にハンバーガーメニュー実装、`md` 未満は折りたたみ。
8. **テーブルに `scope="col"` / `<caption className="sr-only">` を全テーブル付与**。
9. **アイコン絵文字に `aria-hidden="true"`** をテキストラベル隣接時に付与（重複読み上げ抑止）。
10. **`role="status"` / `aria-live="polite"` リージョン**を保存通知・トースト用に layout に常設。

### P2（継続的）

11. **`prefers-reduced-motion` 対応**: `globals.css` にメディアクエリで `transition`, `animation`, `backdrop-filter` を抑制。
12. **見出し階層の整理**: 各ページで `h1` 1個、論理的に `h2 > h3` を保つ規約をlint化（`eslint-plugin-jsx-a11y` 導入）。
13. **`eslint-plugin-jsx-a11y` を `next.config.mjs` 経由で導入**し、CI で違反をブロック。今回検出した htmlFor 欠如・onClickのみ要素・代替テキスト欠如はほぼ自動検出可能。
14. **コントラスト計測の自動化**: `text-ink-500` (#6B7079) on `bg-white` は4.61:1で AA 通過、しかし `text-ink-500/70`、`amber-700/70` (`HealthSection.tsx:121,126,131`) 等の半透明指定は AA 割れの可能性。Lighthouse / axe で全ページスキャン。
15. **200% ズームでのリフロー検証**: `max-w-[1400px]` 固定のレイアウトを `min-w` 縮退対応へ。

## 結論

「触れば動く社内ツール」としては機能するが、WCAG 2.2 AA を満たすにはフォーム/モーダル/フォーカス/レスポンシブの4領域で**全面的な手入れ**が必要。特に**フォーム91入力すべてでラベル関連付けが破綻**している点と、**全モーダルで focus trap が無い**点は、SR/キーボード利用者にとって致命的で、合理的配慮義務（障害者差別解消法 2024年改正）の観点でも社内ツールであっても看過できない。`eslint-plugin-jsx-a11y` の導入と Radix UI 等の準拠コンポーネント採用で、ベースラインを一段引き上げることを強く推奨する。
