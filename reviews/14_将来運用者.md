## 致命的問題

### 1. v1（ルート）と v2（`neo-cs-v2/`）が同居しているが、関係が文書化されていない
- ルート `README.md:1-72` は Vanilla JS + `index.html` (7,238 行のモノリシック HTML) + Vercel Serverless の構成を説明。
- `neo-cs-v2/README.md` は「デモ」と宣言。
- **どちらが本番か、v1 をいつ捨てるか、データ移行は誰がやるかが一切書かれていない**。引継ぎ初日に「`index.html` (`/Users/furuken/dev/neo_cs/index.html`, 7,238 行) は触ってよいのか」を判断できない。
- ルート `package.json:1-7` は v1 を指し、`neo-cs-v2/package.json` は別物。**ワークスペース定義もモノレポ宣言もない**。

### 2. テストが完全にゼロ
- `*.test.*` / `*.spec.*` は `node_modules` 内にしか存在しない（プロジェクト由来は0件）。
- `package.json` に `test` スクリプトすら定義されていない (`/Users/furuken/dev/neo_cs/package.json`, `/Users/furuken/dev/neo_cs/neo-cs-v2/package.json`)。
- リファクタの安全網が皆無。引継ぎ後の最初の変更で必ず壊す。

### 3. CI/CD パイプラインが存在しない
- `.github/workflows/` なし。lint/型チェック/build の自動実行なし。
- デプロイは Vercel の Git 連携任せ（`README.md:5-13`）で、PR 段階での品質ゲートが無い。`tsconfig.json` が壊れても main にマージされ、デプロイ時に初めて気付く構造。

### 4. モック層が「データソース抽象化」になっておらず、本番DB差し替えが極めて困難
- `lib/mock/` 配下は **トップレベルで `export const ... = [...]` と即時生成された静的配列**（例: `entities.ts:21`, `bulk-data.ts:13`, `surveys.ts` 1,120 行, `email.ts` 752 行, `onboarding.ts` 486 行）。
- リポジトリ／サービス層が無く、ページコンポーネントから `import { companies } from "@/lib/mock/entities"` 等で**直接 import している**（`app/companies/page.tsx` 等多数）。
- 本番化には全ページの import 書き換え + `async/await` 化 + Suspense 導入が必須で、機械的置換不可。`lib/mock` を `lib/repositories/` に差し替える設計になっていない。
- さらに `bulk-data.ts:155-158, 207, 218` のように**モジュール評価時に mutable な seed 計算と push を行っている**ため、SSR の並行実行で結果が安定しない潜在バグあり。

### 5. v1 の認証・認可が実質ザル
- `api/auth.js:108-113`: **「最初に登録したユーザーが自動で admin」**という実装。本番運用で初回アクセス者が攻撃者なら admin 奪取。
- `api/db.js:13-16`: Supabase **anon key** で全テーブルを `select/insert/update/delete` 可能。`supabase_schema.sql:25-27` の RLS ポリシーは `using (true) with check (true)` で**実質 RLS 無効化**。`/api/db` エンドポイントには認可チェックが一切無く、誰でも `key` を指定して全データを上書き・削除できる。
- CORS は `Access-Control-Allow-Origin: *` (`api/auth.js:15`, `api/db.js:11`)。

### 6. シークレット管理・環境変数の文書化不足
- `neo-cs-v2/` 側に `.env.example` が無い。v2 は現状モックなので env 不要だが、本番化時に必要な変数が誰にも分からない。
- ルート `.env.example` への参照は `README.md:35` にあるが、ファイルが Git 上に存在しない（`find` でヒットせず）。`.gitignore:7` で `.env` を除外しているのは正しいが、**テンプレが無いため「何を設定すべきか」が口伝**。

## 改善提案（優先度順）

1. **方針宣言**: `CLAUDE.md` をプロジェクト直下に作り、「v1 は凍結。v2 が本番。`index.html` は触らない」「v2 のモックは XX までに repository 層へ差し替える」を明記。
2. **データアクセス層の抽象化**: `lib/repositories/{companies,contracts,surveys,...}.ts` を新設し、`getCompanies(): Promise<Company[]>` 等のインターフェースに統一。実装を `lib/repositories/mock/` と `lib/repositories/supabase/` で切替（環境変数 `DATA_SOURCE=mock|supabase`）。ページからの直接 import を禁止。
3. **テスト基盤**: Vitest + Testing Library を導入し、最低限 `lib/mock` の派生関数（`deriveStatus`, `deriveHealthScore` 等 `bulk-data.ts:8`）と Renewal/Health KPI ロジックにユニットテスト。
4. **CI**: `.github/workflows/ci.yml` で `npm ci && npm run lint && tsc --noEmit && next build` を PR 必須に。
5. **認可**: `api/db.js` をユーザーセッション必須に変更し、Supabase RLS をユーザー単位ポリシーへ書き直す (`supabase_schema.sql:25-27`)。「最初の登録者 = admin」(`api/auth.js:108-113`) を廃止し、初期 admin は環境変数指定 or 手動 SQL に。
6. **README 更新**: v2 の README に「実装済み画面 25 ページ」の現状反映、画面遷移図、ER 図、用語集追加。`.env.example` を v2 にも配置。
7. **巨大ファイル分割**: `lib/mock/surveys.ts` `email.ts` `onboarding.ts` を「型 / 固定データ / 生成ロジック」で 3 分割。`TopNav.tsx` も同様に。
8. **命名統一**: `app/*/XxxView.tsx` に統一する（または `XxxClient.tsx`）。判断基準を CLAUDE.md に明記。
9. **lint/format**: `eslint-config-next` 設定ファイルを明示。Prettier + lint-staged + simple-git-hooks 導入。
10. **v1 廃止計画**: `index.html` と `api/*.js` を `legacy/` へ移動し、`README` に「2026-XX 廃止予定」と明記。
