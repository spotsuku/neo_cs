# NEO CS ポータル v2 — デザインレビュー（UI/UX）

レビュー対象: `/Users/furuken/dev/neo_cs/neo-cs-v2/`
レビュアー視点: シニアUI/UXデザイナー（業務系SaaS／デザインシステム）
基調: 厳しめ。改善余地を遠慮なく指摘する。

---

## 総評

「Liquid Design」と銘打った世界観は意図が明確で、白基調＋すりガラス＋ブランドグラデーションは個性がある。情報密度の高いCS業務にしては珍しく「軽やか」で、ファーストインプレッションは良い。ただし**業務アプリとして要求される"視認性・一貫性・操作性"を、装飾性が幾度も裏切っている**のが本レビューの結論である。

具体には (1) フォントサイズ階層が `text-[10px]` 〜 `text-[11px]` に強く依存しており**WCAG的に厳しいライン**、(2) `liquid-card` と `liquid-surface` の使い分けが曖昧で**事実上のデザイントークンが二重化**、(3) ヘルス／ステータスの色が tailwind カラー（`emerald-500` / `amber-500` / `rose-500`）と raw hex（`#10B981` / `#F59E0B` / `#EF4444`）で**並走**しており、デザインシステムが機能していない、(4) ナビが横一列10項目固定で**狭幅で確実に破綻**、(5) `globals.css` の `liquid-blob` 装飾が**全画面の背後**に常駐し、データ可視化（特にスパークライン・テーブル）の視認性を地味に削いでいる。

「先進性」は感じるが、「業務システムとしての落ち着き」は不足。ロゴグラデーション色を `brand-text-gradient` で見出しに毎回入れる演出は、頻度を絞らないとダッシュボードが**販促LPに見える**。

## 致命的問題

### 1. ナビゲーションが折り返し・優先順位設計を持っていない
`components/TopNav.tsx:7-18` で 10 項目（ダッシュボード／マイページ／受信箱／企業／アンケート／オンボ／週次／更新／出席／設定）が `flex items-center gap-1` の単一行として置かれている。`max-w-[1400px]` 想定で `px-3 py-1.5 text-sm` の Pill が並ぶため、**1280px 未満では右側のユーザー/通知ボタンと衝突**する。`TopNav.tsx:155` の `<nav>` には `flex-wrap` も `overflow` も `responsive` ブレークポイントもない。モバイルメニューやハンバーガー、優先順位低い項目の「もっと見る」も無い。業務アプリの最重要骨格が未設計。

### 2. ラベル長と命名の不統一が IA を壊している
`TopNav.tsx:7-18` で「オンボ」「週次」「更新」「出席」と**動詞も名詞もない2〜3字省略**を多用。一方で「ダッシュボード」「マイページ」「受信箱」はフル表記。ユーザーが「更新＝renewal」「週次＝weekly review」と暗号解読する必要がある。グローバルナビは**省略不可**、別途サブナビ（カードのオプション）で短縮するべき。

### 3. 文字サイズが業務アプリとして小さすぎる
- KPI ラベル `text-xs` (12px)、サブテキスト `text-[11px]`、最小は `text-[10px]` が大量出現
- 例: `KpiCard.tsx:30` `text-xs`, `KpiCard.tsx:38` `text-[11px]`, `ContinuousProductCard.tsx:34` `text-[10px]`, `OneShotProductCard.tsx:28` `text-[10px]`
- `WeeklyTable.tsx:362,388,500` などで `text-[12px]` / `text-[10px]` の入力UI
- `RenewalFunnel.tsx:38,40` の `text-[11px]` 等

10pxフォントは**常用OKラインを下回る**（ガイドライン的に最低12px、推奨14px）。社内とはいえ長時間業務利用を前提にするとアクセシビリティ違反。`HealthDistribution.tsx:27,30,33,36` の凡例 `text-[11px]` / 1.5px ドットも数値が読みにくい。

### 4. デザイントークンの二重化と未統一
- カラー: `tailwind.config.ts:11-35` に `brand` / `product` / `ink` を定義しているのに、コード側では tailwind の素のパレット（`emerald-50`, `amber-50`, `rose-50`, `sky-50`, `violet-50`）と raw hex（`#10B981`, `#F59E0B`, `#EF4444`, `#3D9EFF` …）が混在。`HealthSection.tsx:118-132`, `RenewalFunnel.tsx:5-8`, `app/page.tsx:176`, `InboxView.tsx:28-34` 等。**Healthの「Red/Yellow/Green」が `brand` トークンにも `product` トークンにも入っていない**ことが諸悪の根源。
- カード: `globals.css:20-27` で `liquid-card`（白70%＋blur＋白border）と `liquid-surface`（白＋ink-100 border）の2種類が定義されているが、`liquid-card` はほぼ使われず実態は `liquid-surface` 一択。命名負債。
- 角丸: `rounded-liquid` (1.25rem)、`rounded-2xl`、`rounded-full`、`rounded-lg`、`rounded-md`、`rounded-xl` を場面に応じて使い分けているが**ルールが文書化されていない**。`KpiCard` は `liquid-surface`（=rounded-liquid）なのに、内部のアクセント円は `rounded-full`、Pill は `rounded-full`、テーブルは `rounded-liquid`、トースト系の `rounded-2xl` 等。
- シャドウ: `shadow-liquid` と `shadow-liquid-lg` の使い分けはホバー昇格のみ。良いが利用箇所はかなり限定的。

### 5. 背景の `liquid-blob` がコンテンツの可読性を地味に削る
`app/layout.tsx:13-16` で全画面に 360-420px の彩度ブロブを 3 つ配置。`globals.css:41-47` で `opacity:0.35 / blur(64px)`。`MrrSparkline` のような薄ブルーグラデのチャートや、テーブルの `bg-white/70 backdrop-blur` 系カードと**色が干渉**し、スクロール位置によってKPIの数値背景が薄ピンク／薄グリーンに見える。**業務アプリでは固定背景の彩度ノイズはNG**。プロダクトカードや認証画面など限定的に使うべき。

### 6. `brand-text-gradient` の乱用で視覚階層が壊れている
`app/page.tsx:30`「全体ダッシュボード」、`app/companies/page.tsx:80`「企業」が `brand-text-gradient`（5色グラデ）。**全ページの h1 で同じ多色グラデを使うと、ブランド色の意味が無くなる**。本来は1〜2画面の象徴的見出しのみに留めるべき。今は「LP風の派手見出し」が標準テンプレ化している。

### 7. クリック領域・タッチターゲットが基準未満
- TopNav の Pill: `px-3 py-1.5 text-sm` → 高さ約 28px。Apple HIG の 44pt、Material の 48dp に未達。
- 通知ボタン `TopNav.tsx:179` は `px-3 py-1.5 text-xs`、ユーザー丸 `TopNav.tsx:269` は `w-8 h-8` (32px)。
- `WeeklyTable.tsx:362` のチェックボックス `w-3.5 h-3.5` (14px)。**タッチデバイスでは押せない**サイズ。
- `CompaniesPage` の検索 `px-4 py-2`（高さ 36px 程度）と Pill フィルタ `px-3 py-1`（28px）が**同じ行で並ぶのに高さが違う**（companies/page.tsx:104, 115）。

### 8. グラフ・データ可視化が貧弱
- `MrrSparkline.tsx`: 軸ラベルなし、ホバー時のツールチップなし、データ点のマーカーは末尾のみ (`MrrSparkline.tsx:33`)、目盛無し。**ただのアートワーク**で、12ヶ月のいつ何が起きたか読み取れない。線色は虹のグラデ（緑→青→紫）で**MRRが上下しているように錯覚**させる。
- `HealthDistribution.tsx:22-26`: 100% 棒グラフで `h-2`(8px)。ラベル直付き Stacked bar は良いが、合計が見えるべき場所に `total` の表示がない（`size==="sm"` の場合特に）。0% でも `bg-ink-50` のトラックが残るので、Green=0/Yellow=0/Red=10 のときのバランスが直感的でない。
- `RenewalFunnel.tsx`: 名前は「ファネル」だが**ファネル形状ではなく 3 カラムの単純カード**。Committed→Likely→At Risk が「下から積み上がる」「左から減衰する」など視覚メタファーがない。情報設計に対して命名がミスリーディング。

## 重要な懸念

### A. テーブルの密度・固定列が片手落ち
- `app/page.tsx:154-198` の「要対応企業」テーブル: `px-3 py-3` で行高 ~44px、最右の「対応する →」が `text-xs` テキストリンクのみ。**主要 CTA がプレーンリンクなのは弱い**。プライマリボタンに昇格すべき。
- `WeeklyTable.tsx:101-114` の sticky thead と sticky 左列は良い実装。ただし sticky 列の影 (`border-r border-ink-100`) が弱く、横スクロール時に**列の境界が消える**。`shadow-[2px_0_4px_rgba(0,0,0,0.04)]` 等の右影が必要。
- `MatrixView.tsx:42-58` で `sticky top-0` と `sticky left-0` が混在するが、左上交差セルの `z-30` と `z-20` の関係性に依存しており、ブラウザ実装で厳密性が下がるとちらつく。

### B. アイコン体系が絵文字依存
- `TopNav.tsx:183` 🔔, `TopNav.tsx:313-356` 👤⚙️🔔🌓❓↩
- `app/page.tsx:150` 🚨, `app/page.tsx:163` 🤖
- `HealthSection.tsx:119,124,129` 🟢🟡🔴
- `WeeklyTable.tsx:268,376,389` ⚠✓
絵文字はOSにより**字形・色・サイズ・ベースラインが暴れる**。業務アプリの記号としては不可。Lucide / Heroicons 等の SVG アイコンに統一を。

### C. 状態（成功/警告/危険/情報）の表現が3パターン以上ある
- バッジ: `WeeklyTable.tsx:254-264` (`bg-emerald-50 text-emerald-700 border-emerald-100` 等)
- バッジ: `InboxView.tsx:28-34` (同色だが `STATUS_BG` という別マップ)
- バッジ: `RenewalFunnel.tsx:5-8` (`stageStyle` という別マップ)
- raw hex 直書き: `app/page.tsx:176` (`#EF4444 / #F59E0B`)
全て**同じ目的（ステータスチップ）なのに 4 系統**。`<StatusBadge tone="success|warning|danger|info|neutral" />` のようなコンポーネント化が必須。

### D. ホバー・フォーカスの一貫性
- リンク類は `hover:underline` / `hover:bg-ink-50` / `hover:text-ink-700` がランダム。
- フォーカスリングが**全コンポーネントで未指定**（`focus:outline-none focus:border-ink-300` のみ）。例: `companies/page.tsx:104,136`、`WeeklyTable.tsx:400,446,501`。**キーボード操作時にどこにフォーカスが当たっているか不可視**。アクセシビリティ違反。
- ボタンの :active / :disabled も未定義。

### E. インタラクション・フィードバック不足
- 通知メニュー (`TopNav.tsx:189-262`) を開いてもアニメーションなし（pop-in なし）。
- WeeklyTable の編集 (`WeeklyTable.tsx:171-247`) は即時保存・autosave なのか手動保存なのか不明（保存ボタン非表示）。`draftDirty` バッジ (`WeeklyTable.tsx:257-260`) は出るが、**保存タイミングのアフォーダンスがゼロ**。
- KpiCard / ContinuousProductCard が `<button>` (`ContinuousProductCard.tsx:29`, `OneShotProductCard.tsx:23`) なのに **onClick 未バインド**。クリック可能に見えてクリックしても何も起こらない（誤誘導）。

### F. エンプティ／エラー／ローディング状態
- 空状態: `companies/page.tsx:270-279`「該当する企業がありません」のみ。**イラスト・原因説明・CTAなし**。
- ローディング状態: 全画面で**未定義**（Skeleton コンポーネントが存在しない）。Next.js の `loading.tsx` も用意されていない。
- エラーUI: `error.tsx` 未配置。例外時に Next.js 既定の赤画面が出る。

### G. ブランディングと業務トーンの衝突
- ロゴ `BrandMark.tsx`: SVG の "N"（V字を 2 つ）がフォント加工感が強く、ピクセル単位 (`size * 0.7`) でクロップされていてバランスが悪い。28px 既定では**白縁の "M" にしか見えない**。
- 5色グラデ（緑→青→紫→ピンク→橙）はモダンだが、CSの「緊急度・健全度・財務」と**色相が完全衝突**（緑＝Health Green、ピンク＝brand-pink、橙＝brand-orange なのに warning 的な amber も併存）。意味色とブランド色を明確に分離するべき。

### H. レイアウトの最大幅と余白
- `max-w-[1400px]` を全画面で固定 (`app/page.tsx:24`, `companies/page.tsx:74`, `TopNav.tsx:147`)。1080p ノートでは適正だが、4K や WUXGA 縦並びでは中央に詰まりすぎる。テーブル系は `max-w-none` に切り替えるべき。
- セクション間 `space-y-10` (`app/page.tsx:24`) は緩やかで好印象。一方 `companies/page.tsx:74` は `space-y-6`。**ページ毎にスケールが違う**。

## 評価できる点

- `liquid-surface` ＋ `shadow-liquid` で**白基調のソフトな統一感**は出せている。多くのSaaSが「グレー背景+白カード」一辺倒なのに対し、白背景+影で軽やかさを出せている。
- `ProductBadge`（`components/ProductBadge.tsx`）が 1 ファイル化されており、アクセント色と短縮名のマッピングがきちんと中央集約。**プロダクトカラー運用は良い設計**。
- `TopNav.tsx:204-243` の通知ドロップダウンの情報密度・カテゴリチップ・未読ドット・タイムスタンプは**プロダクト品質**。同様の品質をテーブルや他のドロップダウンに広げたい。
- `HealthSection.tsx:67-111` のフィルタ Pill（複数選択可、選択中はアクセント色のうっすら背景）は意味合いと操作感が一致。
- `WeeklyTable.tsx` の sticky 行＋ sticky 列＋ zebra＋詳細展開 (`WeeklyTable.tsx:281-298`) はかなり凝っており、業務密度に向き合っている。
- `tailwind.config.ts` の `ink` グレースケール 6 段階は適切な粒度。
- `KpiCard.tsx:24-29` のアクセント円ボケは控えめで上品。これは残すべき。

## 改善提案（優先度順）

### P0（次スプリントで着手）

1. **デザイントークン整理**
   - `tailwind.config.ts` に `semantic` レイヤを追加: `success / warning / danger / info / neutral` の 50/100/500/700 をそれぞれ定義し、`brand`・`product` と完全分離。`HealthSection.tsx`, `RenewalFunnel.tsx`, `InboxView.tsx`, `WeeklyTable.tsx` の raw hex / emerald-* / amber-* / rose-* を全置換。
   - `<StatusBadge tone>` `<HealthDot color>` `<Card variant="surface|raised|glass">` を `components/ui/` 配下に切り出し。
2. **タイポグラフィ最小値を引き上げ**
   - `text-[10px]` `text-[11px]` を全廃。最小は `text-xs` (12px)。本文系 `text-sm` (14px) を基準に。`KpiCard.tsx:30,38`、`ContinuousProductCard.tsx:34,36,42,46,50,54`、`HealthDistribution.tsx:27` 等を一括修正。
3. **ナビゲーションの再設計**
   - 主要 5 + その他ドロップダウン構成へ。例: 「マイページ／受信箱／企業／週次／更新」+「⋯ その他（オンボ／アンケート／出席／設定／レポート）」。
   - `TopNav.tsx` を `<DesktopNav />` `<MobileNav />` に分割し、ブレークポイント `md` 以下はハンバーガーへ。
4. **背景 blob の撤去 or 限定使用**
   - `app/layout.tsx:13-16` を削除。ブランド表現はログイン画面・空状態イラストに限定。
5. **`brand-text-gradient` の使用箇所を 1〜2 画面に限定**
   - 既定の h1 は `text-ink-900` ＋ accent under-bar 等に。

### P1（数週間内）

6. **アクセシビリティ基本対応**
   - `:focus-visible` リング (`focus-visible:ring-2 focus-visible:ring-ink-900 focus-visible:ring-offset-2`) を `Button` `Link` 共通化。
   - `aria-label` を絵文字ボタンに付与。長期的には絵文字 → SVG アイコン (`lucide-react` 推奨) へ。
   - チェックボックス・ラジオは最低 16px、推奨 20px。
7. **状態UIテンプレート化**
   - `app/loading.tsx` `app/error.tsx` `components/Empty.tsx` を作成し、各画面に適用。
   - WeeklyTable 等の autosave に対し、トースト or インライン「保存しました ✓」表示。
8. **クリッカブル要素のアフォーダンス強化**
   - `KpiCard`/`ContinuousProductCard`/`OneShotProductCard` を `<button>` ではなく `<Link href>` に。または onClick を必ず接続。
   - 主要テーブルの末尾アクション（「対応する →」）をプライマリボタン（黒丸ボタン）に。
9. **データビジュアル強化**
   - `MrrSparkline` にツールチップ・X軸ラベル（4半期目盛）・前年比注釈を追加。色は単一ブランドカラーに（虹は止める）。
   - `RenewalFunnel` を真の funnel グラフへ（横長台形 3 段、または積み上げ横棒）。
   - `HealthDistribution` に hover ツールチップ＋ aria-label（「Green 8件、Yellow 3件、Red 2件」）を付与。

### P2（中期）

    - `components/ui/` 配下に `Button` `Badge` `Card` `Input` `Select` `Dropdown` `Table` `EmptyState` を集約。Storybook 導入。
11. **ダークモード設計**
    - 「テーマ」メニュー (`TopNav.tsx:341-348`) はあるが実装なし。`ink-*` を CSS 変数化し、`prefers-color-scheme` 対応。
12. **ロゴ刷新**
    - `BrandMark.tsx` の SVG を再設計。28px / 24px / 20px の各サイズで**読み取れる字形**を専用に作る（small-pixel optimized）。
13. **印刷／レポート出力ビュー**

## 一言

「Liquid Design」の方向性は正しい。だが現状は**コンセプトが先行し、デザインシステムがまだ存在していない**。ブランド表現を 30% 削り、その分をトークン整備・タイポ拡大・状態 UI 整備に回せば、業務アプリとして頭一つ抜ける。今のままでは「綺麗だけど現場で使うと細かいストレスが溜まる」プロダクトに着地する。
