## 総評（辛口）

きれいな「ダッシュボードの絵」は出来ているが、**事業の意思決定に使えるアプリにはまだ程遠い**。全画面がハードコードされたモックデータ（`neo-cs-v2/lib/mock/*.ts`、計4,500行超）で動いており、ダッシュボード `app/page.tsx:13-18` も `snapshot/alerts/upcoming/mrrTrend` をモックから直接 import している。一方バックエンドは旧世代の素のNode HTTPサーバ（`server.js`）と、**全データを `key, value` の1テーブル(`ps_data`)** に放り込むだけのスキーマ（`supabase_schema.sql:5-10`）で、新フロントとの接続線が一切引かれていない。フロントとバックが**別世代の別アプリ**として並行存在しており、このまま進めると「見栄えのいいPOC」に数百万円を溶かす典型パターンになる。NEO福岡規模（取引中42社・MRR 842万円, `data.ts:133-141`）で、Gainsight/HubSpotを自前で再発明する経済合理性は説明できない。

## 致命的問題

1. **本番データに1度も触れていない（モック前提のフロント）**
   - ダッシュボードのトップ KPI 4枚は `data.ts:133-141` の固定値（取引中企業 42 / MRR 8,420,000 / At-Risk 7）。
   - At-Risk テーブル `app/page.tsx:168` は `alerts`（`data.ts:327-407`）を直接 map。**実データのトリガはどこにも存在しない**。
   - `lib/mock/` 配下は `surveys.ts` 1,120行、`email.ts` 752行など総計 **4,502行のダミー**。これは「DB設計の代替」になっており、移行作業は事実上の作り直し。

2. **DBスキーマが事業要件に対して破綻している**
   - `supabase_schema.sql` は `ps_data(key text, value jsonb)` のみ。会社・契約・参加者・健全度・更新ファネルといった**主要エンティティが1つも正規化されていない**。
   - RLSポリシーが `for all using (true)`（`supabase_schema.sql:29-30`）。anon キーで全行 R/W 可能。**事実上認証なし=顧客データを置けない**。
   - フロントの ProductCode/Cycle/Course モデル（`data.ts:5-128`）はDB側に対応する表が存在しない。

3. **2つのアプリが並走している（旧 index.html + 新 Next.js）**
   - `server.js:70-74` は `index.html` を返す旧スタック。新しい `neo-cs-v2/` (Next.js 16) とは無関係。
   - `api/claude.js` `api/db.js` `api/auth.js` は旧フロント前提で書かれており、新フロントから呼び出している箇所はゼロ（`grep` 結果: `app/` `lib/` 配下に `fetch(` `supabase` の呼び出しなし）。**バックエンドの存在が経営上の意味を持っていない**。

4. **経営判断KPIが構造的に欠落**
   - 解約率(Churn)、CAC、CAC回収月数、LTV、グロス/ネットチャーン、コホート別維持率、セグメント別NRR、**いずれも `data.ts` に存在しない**。あるのは NRR 単一値（`continuousSummary` 内の 1.08 / 0.96 / 0.91）のみで、計算根拠なし。
   - 「経営向けKPIサマリー」テンプレ（`app/reports/page.tsx:36-42`）は**タイトルとアイコンだけ**で出力ロジック未実装。`lastExportedAt` すら固定文字列。
   - MRR推移（`data.ts:431-444`）は単調増加の手書き値。**新規/拡張/縮小/解約のブレイクダウンがない=PLとして読めない**。

5. **AI推奨アクション(`alerts[].suggestedAction`)が静的文字列**
   - `data.ts:345, 355, 365…` 全て手書き。LLM接続もスコアリングロジックも存在しない。**「🤖 AI推奨」(`page.tsx:163`) は表示上のラベル詐称**に近い。

## 重要な懸念

- **認証/権限**: `api/auth.js` に Google OAuth の骨格はあるが、Next.js 側 `app/layout.tsx` `TopNav.tsx` には未接続。社内CS（顧客機微情報含む）を扱う前提として、権限分離が「設計図」段階。
- **報告のExport機能が空**: `app/reports/page.tsx` の6テンプレートは全てダミー。`lastExportedAt` が固定値（`templates[0].lastExportedAt:"2026-04-15 10:23"` 等）でデモ用。本番では「何も出ない」。
- **データ規模の経済合理性**: 取引中42社・MRR 842万円（年商約1.3億ペース）に対し、自社開発のフルスタックCS基盤を維持する内製コストは年1名の人件費でも投資回収困難。HubSpot Service Hub Pro / Gainsight PX / 国産PRMでも 月数万円〜数十万円で同等可視化が可能。
- **競合優位の不在**: 本アプリ独自の差別化要素は「研修プロダクト4種(ACADEMIA/評議会/AIKEN/コミュマネ)の業務語彙にフィットさせたUI」のみ（`data.ts:11-76`）。これは Gainsight/HubSpot のカスタムプロパティで再現可能。**「自前で作らないと死ぬ」要素は1つも見当たらない**。
- **技術スタックのリスク**: Next.js 16 + React 19 は最新すぎて社内に保守できる人材が古野氏一人になっている可能性。バス係数=1。
- **会計連携・売上ソース**: freee 等 SoR との接続が一切なし。MRR は手入力前提で**経理と数字が合わなくなる将来コスト**を抱える。

## 評価できる点

- **業務理解の解像度は高い**: 「期/回」「継続型/単発型」（`data.ts:7-9`）、コース概念（`data.ts:96-111`）、健全度×アラート×推奨アクションの3点セット（`data.ts:327-407`）、更新ファネル(Committed/Likely/At-Risk, `data.ts:162-194`) など、CSオペの構造化が秀逸。**要件定義書としての価値**は十分にある。
- **画面構成の情報設計が良い**: `app/page.tsx` の① スナップショット → ② Health → ③ 更新ファネル → ④ 期間 → ⑤ MRR/イベント → ⑥ 研修別 → ⑦ 要対応、という導線は経営定例にそのまま使える。
- **UI/UXのクオリティ**: liquid-surface / brand-text-gradient（`page.tsx:30, 91`）など、社内ツールとしては過剰なほど洗練されている。
- **モジュール分割**: `components/` (KpiCard, HealthSection, RenewalFunnel 等) が用途で綺麗に切れており、データを差し替えれば本番化は技術的には可能。

## 経営判断の提言

1. **「自社開発を続けるか」を今、意思決定する**
   - 現状はPOC/要件定義としては優秀、プロダクトとしては未着手。**3ヶ月以内に「実データに繋がる」マイルストーンを置けないなら撤退**し、HubSpot/Gainsight + Looker Studio に乗せ替えるのが合理的。年300万円以下で同水準は買える。

2. **続けるなら "Mock撤廃Sprint" を最優先タスクに**
   - `supabase_schema.sql` を破棄し、companies / contracts / participants / health_scores / renewal_stages / events / mrr_monthly の正規化スキーマに作り直す。
   - `lib/mock/*.ts` の型定義をそのまま Prisma/Drizzle スキーマに変換し、API層（Next.js Route Handlers）を `app/api/` 配下に1本化。`server.js` と `api/*.js` は廃止。
   - RLSは `auth.uid()` ベースに必ず書き換え。`using (true)` のままでは1件の顧客データも入れてはいけない。

3. **経営KPIを"見える化"の前にまず"定義"する**
   - 解約率(月次/年次/Logo/Revenue別)、グロスチャーン、ネットチャーン、NRR/GRR、CAC、CAC Payback、LTV、セグメント別NRR、コホート維持率。**これらの算式と元データの所在を1枚にまとめる**。データソースは freee（売上）+ 本アプリ（契約状態）の2系統に絞る。

4. **「AI推奨」を本物にするか、ラベルを外すか**
   - LLM API 接続(`api/claude.js`)は既にある。アラート×直近接点×NPS変動を入力にした推奨アクション生成を1機能だけ本実装し、それ以外の "🤖" 表記は外す。**機能詐称はCSメンバーの信頼を蝕む**。

5. **組織コスト**
   - 古野氏の工数換算で本プロジェクトに掛かっている時間 × 時給 を月次で可視化し、「同期間にHubSpot導入していたら何が出来たか」と並べて月次レビュー。**機会費用の見える化なしに内製は判断できない**。

---

**結論**: 「要件定義書つきの動くワイヤーフレーム」としては A 評価。「事業基盤プロダクト」としては D 評価。**今、SaaS購入と内製継続のどちらに賭けるかを意思決定する時期**。判断を半年先送りすると、サンクコストで撤退できなくなる。
