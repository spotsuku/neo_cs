# neo_cs 本番化ロードマップ

mockプロトタイプから本番アプリへ移行するための作業を **4本の会話ストリーム** に分割。
各ストリームは独立したClaude Code会話として進める。最初に **01_基盤** を完了させること。

## ストリーム構成と依存関係

```
[01_基盤]  ← 必ず最初。他の全ての前提
   │
   ├─→ [02_機能改修]     ← 基盤完成後に開始
   ├─→ [04_運用セキュリティ] ← 02と並走可能
   │
[03_デザインUX]  ← いつでも並走可能 (基盤に依存しない)
```

## 各ストリームの責務

| # | ストリーム | 主要スコープ | 着手タイミング |
|---|---|---|---|
| 01 | 基盤 | DBスキーマ正規化 / 認証 / RLS / リポジトリ層 / mock撤去計画 | 最優先・単独 |
| 02 | 機能改修 | Health算出 / 解約予兆 / KPI正確性 / 保存導線 / メンバーマスタ | 01完了後 |
| 03 | デザイン/UX | デザイントークン / ナビ再設計 / A11y / 入力UX | 並走可 |
| 04 | 運用/セキュリティ | 監査ログ / CORS / レート制限 / CI/テスト / バックアップ / 監視 | 02と並走 |

## レビュー視点との対応

- 01_基盤 ← 経営者, データアナリスト, 将来運用者, 情シス(基盤部分), 法務(基盤部分)
- 02_機能改修 ← CS責任者, CS入力者, CSマネージャー, 事業/営業, 財務経理, 顧客
- 03_デザインUX ← デザイナー, 新人CS, アクセシビリティ
- 04_運用セキュリティ ← 情シス(運用), SRE, 法務(運用), 他部署連携

詳細は各 `01_*.md` 〜 `04_*.md` を参照。
各ファイルが独立した会話の冒頭プロンプトとして使える形式になっている。
