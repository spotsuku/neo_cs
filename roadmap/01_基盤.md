# ストリーム01: 基盤 (DB / 認証 / RLS / リポジトリ層)

> このファイルを新規Claude Code会話の冒頭に貼り付けて開始する。
> 完了するまで他のストリームを始めないこと。

## 目的
mockハードコードから本番DBに繋ぎ込むための土台を作る。
他の全ての改修 (機能・デザイン・運用) はこの基盤の上に乗る。

## 前提となる現状の問題 (レビューで判明済み)

- `supabase_schema.sql` は `ps_data(key, value jsonb)` のKVS1テーブルのみ。RLSは `allow_all` 全開放
- 全画面が `lib/mock/*.ts` (約4,500行) を直接import
- `api/auth.js:107-108` で初回ユーザーを自動admin化
- 監査ログ・イベントログなし
- mockとDBの境界 (リポジトリ層) が存在しない
- v1 (`server.js` + `api/`) と v2 (`neo-cs-v2/`) が併存しており接続方針未定

## このストリームで完了させるスコープ

### A. データモデル設計
- [ ] ドメインモデルを正規化スキーマに落とす (companies, contracts, products, users, cycles, weekly_reviews, surveys, onboarding_tasks, health_snapshots, churn_events, audit_logs 等)
- [ ] `lib/mock/entities.ts` の型定義を正本にしてSQLへ変換
- [ ] イベントログテーブル (時系列分析の基盤) を必ず含める
- [ ] 外部キー、インデックス、制約 (NOT NULL, CHECK) を明示

### B. 認証・認可
- [ ] Supabase Auth に切替 (現在の自前auth.js廃止)
- [ ] RBAC: roles テーブル (admin / manager / member / viewer)
- [ ] 初回ユーザー自動admin化を撤廃 (招待制 or 環境変数で初期管理者指定)
- [ ] セッション管理、CSRFトークン、httpOnly Cookie

### C. RLSポリシー
- [ ] `allow_all` を全廃
- [ ] テーブル毎にロール別read/writeポリシーを書く
- [ ] 個社情報は担当者+マネージャー+admin のみ閲覧可、等
- [ ] anon ロールには何も許さない

### D. リポジトリ層
- [ ] `lib/repository/` を新設し、画面はここ経由でデータアクセス
- [ ] 初期実装はmockをラップしたmockRepository
- [ ] supabaseRepositoryへの差し替えがフラグで切れる構造に
- [ ] 段階的移行: 1画面ずつmock→DBに切替

### E. v1/v2 統合方針決定
- [ ] `server.js`+`api/*.js` を廃止するか、`neo-cs-v2`内のRoute Handlerに統合するか決定
- [ ] `index.html` (XSSあり) は廃止

### F. 環境変数・シークレット
- [ ] `.env.example` 作成
- [ ] Supabase URL/anon key/service role key の管理方針
- [ ] Anthropic API key を サーバー側のみに閉じる

## 完了条件 (Definition of Done)

1. `supabase_schema.sql` が正規化されRLSが本番運用可能
2. ログイン→自分が担当する会社一覧、が本物のDBから出てくる
3. mockRepository ↔ supabaseRepository を環境変数で切替可能
4. `npm run build` が通り、型エラーゼロ
5. 認証バイパス・RLS漏れ・初回admin問題が解消
6. `roadmap/01_基盤_完了報告.md` に実装内容と「次ストリームへの引き継ぎ事項」を残す
