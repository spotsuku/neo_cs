# ストリーム04: 運用 / セキュリティ強化

> このファイルを新規Claude Code会話の冒頭に貼り付けて開始する。
> **前提**: 基盤(01)が完了していること。02と並走可能。

## 目的
本番運用に耐える可用性・監視・セキュリティ・コンプライアンスを整える。
01で骨格は作った前提で、運用層を厚くする。

## 前提となる現状の問題 (レビューで判明済み)

- 監査ログ皆無 (誰がいつ何にアクセスしたか不明)
- CORS全許可 (`Access-Control-Allow-Origin: *`)
- `/api/claude` がレート制限・認証なしの無制限プロキシ
- `index.html` にStored XSS
- ヘルスチェックエンドポイントなし
- バックアップ・リストア手順なし
- 構造化ログなし、エラー監視なし
- タイムアウト未設定 (依存サービス障害時にハング)
- テスト/CIがゼロ
- 同意UI、利用目的明示なし
- メール本文を米国Anthropicに無同意送信 (個情法28条相当)
- 削除フロー未実装
- 自動評価への異議申立権なし
- 退職者アクセス遮断手順なし
- CRM/Slack/Webhook連携なし
- 通知がCS内に閉じている

## このストリームで完了させるスコープ

### A. 監査・コンプライアンス
- [ ] `audit_logs` テーブルへの全変更記録 (誰が・いつ・何を)
- [ ] 利用規約・プライバシーポリシー同意UI
- [ ] 顧客企業ごとの利用目的明示
- [ ] データ削除フロー (顧客契約終了時、退職者)
- [ ] 自動評価への異議申立フォーム
- [ ] Anthropic API利用前の組織同意フロー (claude.js のメール解析)

### B. セキュリティ強化
- [ ] CORS を許可ドメインホワイトリスト化
- [ ] `/api/claude` に認証 + レート制限 (per-user, per-org)
- [ ] CSPヘッダー、HSTS
- [ ] 依存パッケージの脆弱性スキャン (`npm audit`, Dependabot)
- [ ] シークレット管理 (Vercel/Supabase の環境変数)
- [ ] セッションタイムアウト、強制ログアウト

### C. 監視・可観測性
- [ ] 構造化ログ (pino等)
- [ ] エラー監視 (Sentry)
- [ ] APM (Vercel Analytics or Datadog)
- [ ] ヘルスチェックエンドポイント `/api/health`
- [ ] アラート通知 (Slack)

### D. 信頼性
- [ ] 全外部呼び出しにタイムアウト + リトライ
- [ ] バックアップ手順 (Supabase point-in-time + 検証)
- [ ] リストアのRunbook
- [ ] 依存サービス障害時の縮退運転 (Anthropic, Gmail)
- [ ] N+1検出と修正

### E. テスト・CI/CD
- [ ] ユニットテスト (Vitest)
- [ ] E2Eテスト (Playwright) — 主要動線
- [ ] GitHub Actions: lint + typecheck + test + build
- [ ] PRごとのプレビューデプロイ
- [ ] ロールバック手順

### F. 他部署連携
- [ ] Slack通知 (アラート、解約予兆、エクスパンション機会)
- [ ] Notion連携 (VOC→開発)
- [ ] 公開API or Webhook (営業ツール連携)
- [ ] 部署別ロール (営業は閲覧のみ等、01と協調)

### G. 退職者・契約終了対応
- [ ] ユーザー無効化フロー
- [ ] 個社契約終了時のデータ取り扱い (削除/匿名化/保管期限)

## 完了条件 (Definition of Done)

1. CIが全PRで通る (lint + type + test + build)
2. axe DevTools, npm audit, セキュリティスキャン通過
3. 監査ログが全変更で記録される
4. Sentry/ログ基盤に本番イベントが流れる
5. Runbook (障害対応・バックアップ・リストア) が `docs/runbook/` にある
6. 同意UI、削除フロー、異議申立が機能する
7. `roadmap/04_運用セキュリティ_完了報告.md` 残す
