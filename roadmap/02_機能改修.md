# ストリーム02: 機能改修 (CSロジック / KPI / 入力UX)

> このファイルを新規Claude Code会話の冒頭に貼り付けて開始する。
> **前提**: ストリーム01_基盤が完了していること。

## 目的
画面はあるがロジックが空、という状態を解消する。
CSが本当に業務で使え、経営が信頼できる数字を出せるアプリにする。

## 前提となる現状の問題 (レビューで判明済み)

- Healthスコアが `renewalStatus` 色定数の写像に過ぎない (`contracts.ts:64`, `HealthSection.tsx:135`)
- 解約予兆エンジンは存在せず、`alerts` はハードコード (`churn.ts`)
- 更新マイルストーンが日付経過で自動done (`cycles.ts:165`) — 形骸化
- 保存ボタン未配線 (`CompanyWeeklyEditor.tsx:259`, `WeeklyReviewPanel.tsx:380`, `companies/new/page.tsx:47`)
- ドラフトlocalStorage永続化なし、離脱警告なし
- メンバーマスタ不在 (4ファイルでハードコード)
- MRRハードコード、Q1値とFY値が同一の不具合
- エクスパンション/NRR導線ゼロ、CS as Profit Center 思想欠如
- VOC→開発フィードバックループなし

## このストリームで完了させるスコープ

### A. データ入力の救済 (P0)
- [ ] 全編集画面に保存ボタンを配線 (リポジトリ層に書き込み)
- [ ] オートセーブ + 明示保存のハイブリッド
- [ ] 離脱時の警告 (`beforeunload`)
- [ ] ドラフトlocalStorage永続化
- [ ] Tab移動順、フォーカス管理
- [ ] 削除前の確認ダイアログ
- [ ] CSV import の robust化 (現在は素朴split)

### B. メンバーマスタとアサイン
- [ ] `users` テーブルから担当者を引く (ハードコード撤廃)
- [ ] 個社×担当CSの関係テーブル
- [ ] メンバー×担当社数×稼働×品質ダッシュボード (`/team`)
- [ ] 1on1ログ機能

### C. Healthスコア再設計
- [ ] スコアの算出根拠 (`factors`) を実データから計算
- [ ] 説明可能性: 「なぜこのスコアか」を画面に表示
- [ ] 顧客個人へのat_riskラベルを廃止 (法人単位に)
- [ ] スコア変動の時系列グラフ

### D. 解約予兆エンジン
- [ ] ルールベース: 利用頻度低下、ミーティング欠席、スコア急落 等
- [ ] 該当時にアラート + Slack通知 (連携は04ストリームと協調)
- [ ] 解約理由を事前カテゴリ化、顧客に確認

### E. KPI計算の本物化
- [ ] MRR/ARR/Churn/NRR/At-Risk MRR を契約データから動的計算
- [ ] Q1とFY値の不具合修正
- [ ] ダッシュボードに計算根拠リンク (透明性)
- [ ] 月次・週次のスナップショット保存 (時系列分析の素地)

### F. エクスパンション/アップセル
- [ ] アップセル機会の検知ロジック
- [ ] 営業への引き継ぎ導線 (Slack/メール通知 → 04ストリーム協調)
- [ ] エクスパンションMRRをダッシュボードに

### G. 更新マイルストーン
- [ ] 日付経過の自動done廃止 → 担当者の明示完了
- [ ] T-120/90/60/30 の各タスクに証跡フィールド

### H. VOCループ
- [ ] アンケート/コメントから「プロダクト要望」をタグ付け
- [ ] 開発チーム向けエクスポート (Notion/Linear連携は04へ)

## 完了条件 (Definition of Done)

1. CS入力者が1日の業務をmockなしで完結できる
2. ダッシュボードの全KPIが計算根拠をクリックで追える
3. Healthスコアの根拠が画面に明示される
4. 解約予兆アラートが実データから出る
5. メンバーマスタからの担当者表示
6. `roadmap/02_機能改修_完了報告.md` 残す
