# ストリーム03: デザイン / UX / アクセシビリティ

> このファイルを新規Claude Code会話の冒頭に貼り付けて開始する。
> 基盤(01)に依存しないため、いつでも並走開始可能。

## 目的
業務アプリとして「使える」デザイン・情報設計に整える。
新人でも迷わず、ベテランでも疲れず、視覚障害者にも使えるレベルへ。

## 前提となる現状の問題 (レビューで判明済み)

- ナビゲーション情報設計が未確立 (ラベル略語、階層曖昧)
- 10〜11pxの過小フォント多用
- デザイントークン二重化 (emerald/amber/rose と raw hex 並走)
- `liquid-blob` 背景が可読性侵食、`brand-text-gradient` 乱用
- フォーカスリング皆無、`focus:outline-none` を29箇所で代替なし
- スパークラインに軸/ツールチップ無し
- 91入力で `htmlFor` 未設定
- 3モーダル全てfocus trap無し
- 色のみで情報を伝えている (Healthスコア)
- ヘルプ全リンクが `href="#"` で機能不全
- 専門用語の説明ゼロ
- スキップリンク欠如、`lang="ja"` は良いが他のa11y欠落

## このストリームで完了させるスコープ

### A. デザインシステム整備
- [ ] デザイントークン一本化 (色・タイポ・余白・角丸・シャドウ)
- [ ] `tailwind.config.ts` に集約、raw hex 撤廃
- [ ] フォントサイズ最小値を14px (本文)、12px(補助)に
- [ ] `liquid-blob`, `brand-text-gradient` を業務向きの落ち着いた表現に
- [ ] フォーカスリング全要素に復活 (`focus-visible:`)

### B. ナビゲーション再設計
- [ ] IA再構築 — 主要動線とサブ動線の階層を明示
- [ ] ラベル: 略語廃止、業界用語にツールチップ
- [ ] ブレッドクラム or 戻る導線
- [ ] アクティブ状態の視認性

### C. データ可視化の改善
- [ ] スパークラインに軸/ツールチップ/単位
- [ ] Healthスコアを色+数値+テキストの三重表現
- [ ] 凡例とエクスポート機能
- [ ] 空データ時のエンプティステート

### D. 入力UX (02ストリームと協調)
- [ ] フォームのラベル全付与 (`htmlFor`)
- [ ] エラーメッセージの関連付け (`aria-describedby`)
- [ ] バリデーションタイミング (blur/submit)
- [ ] キーボードショートカット (Cmd+S 保存等)

### E. アクセシビリティ (WCAG 2.2 AA準拠)
- [ ] スキップリンク追加
- [ ] モーダルのfocus trap (Radix UI 導入推奨)
- [ ] 色のみで判断不可な箇所をアイコン/テキスト併記
- [ ] コントラスト比チェック、AA基準達成
- [ ] `eslint-plugin-jsx-a11y` 導入してCIで検査
- [ ] スクリーンリーダー検証

### F. 新人向けオンボーディング
- [ ] ヘルプページの全リンク実装
- [ ] 用語集ページ (健全度/サイクル/ファネル等)
- [ ] 各画面に初回ツールチップ
- [ ] エンプティステートにガイダンス

### G. レスポンシブ・モバイル
